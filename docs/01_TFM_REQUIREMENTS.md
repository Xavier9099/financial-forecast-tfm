# 01 — Requisitos oficiales del TFM (checklist)

Fuente: *Guía para realizar el Trabajo Fin de Máster* (UCM). Modalidad elegida:
**Opción 1 — Análisis de un dataset (orientación Data Scientist)**.

## Memoria
- [ ] Máximo **20 caras** tamaño folio (sin portada, contraportada, índice ni anexos).
- [ ] Tipografía Verdana o Arial, tamaño 10-11.
- [ ] Orientación de **negocio**: predomina la explicación sobre el detalle técnico.
- [ ] Fases delimitadas: descriptivo → transformaciones → modelos → interpretabilidad → conclusiones.
- [ ] Mejoras aportadas por el modelo explicitadas; líneas futuras.
- [ ] Bibliografía breve (≤ media cara, cuenta dentro de las 20).
- [ ] Formato PDF / DOCX / HTML. **No PowerPoint. No formato de paper.**

## Vídeo
- [ ] MP4, **máximo 5 minutos**, idealmente < 50 MB.
- [ ] Voz en off obligatoria; no es necesario aparecer en imagen.
- [ ] Debe describir el proyecto (enfoque, conclusiones, lecciones), no ser un elevator pitch.

## Anexos (no cuentan para las 20 caras)
- [ ] Código desarrollado.
- [ ] EDA detallado y ejecución de modelos.

## Código y acceso
- [ ] Repositorio GitHub público o Drive accesible desde el link.
- [ ] **Carlos Ortega y Santiago Mota** con permisos de acceso.
- [ ] Proyecto reproducible.

## Otros
- [ ] Derechos de uso de los datos revisados y documentados.
- [ ] Fichero: `Xavier_Gutierrez_Palma_<titulo>.zip`.
- [ ] Trabajo individual.
- [ ] Se valora muy positivamente la **productivización** → demo Streamlit.
- [ ] Se valora el uso de **conjuntos grandes** → panel de ~15.000 filas × 30+ features.

## Riesgos señalados por la guía que aplican a este TFM
- Evitar datasets ampliamente tratados en blogs → justificar explícitamente en la memoria que
  el dataset es **construido**, no descargado, y que el aporte está en el protocolo y el ensemble.
- Un cuadro de mando sin modelización es insuficiente → aquí la modelización es el núcleo.
- **No se admiten cambios de tema a menos de 15 días de la entrega.**
